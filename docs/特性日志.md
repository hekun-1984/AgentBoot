# 特性日志

记录框架相对「只把 SKILL.md 当作提示词」新增的运行时能力。日期：2026-10-16。

## 契约直接驱动执行

- `SKILL.md` 的 `output` 字段默认必填。缺字段，或值的类型与 `type` 不一致时，按该 Agent 的 `on_failure` 处理，`error_kind` 为 `llm`。
- `required_tools` 列出结束前必须成功调用的 Tool，且必须出现在 `tools` 里。模型想直接结束时，运行时会把它送回去调用；步数用尽仍未调用，则按失败策略结束。
- 子图的 `reads` 在子图启动前检查。缺字段时不进入内部 Agent，错误类型为 `state`。可选上下文不要写进 `reads`。

糖尿病示例里，取数、指南、饮食、运动、复查这几个 Agent 已声明各自的 `required_tools`。风险评估子图、管理计划子图和紧急子图的 `reads` 是 `patient_id` 与 `user_input`；指南子图只要求 `user_input`。

## 兜底由业务声明

主图不再写死 `risk_level`。业务在主图上声明三件事：

- `guard_field`：看 `shared_context` 的哪个字段
- `guard_values`：哪些值触发兜底
- `guard_subgraph`：强制进入哪张已注册子图

`screen()` 仍负责路由前的规则检查。`emergency_subgraph` 只在 `screen()` 把 `force_emergency` 设为真时使用。

糖尿病主图的声明是：`risk_level` 为 `high` 或 `critical` 时进入 `emergency_escalation`。

## 一次调用的审计记录

每次 `invoke` 生成一个 `call_id`，并写进这次调用里的主图、子图、Agent、模型和 Tool span。

可替换出口：

- `MemoryTraceSink`：留在内存，测试和当场重放使用
- `JsonlTraceSink(path)`：按 JSONL 追加到文件

`AgentBootApplication(trace_sink=...)` 或 `invoke(..., trace_sink=...)` 指定出口。不传出口时，记录只在返回值里。

`replay(record)` 用记录中的 `user_input` 和 `context` 再跑一次，供回归对比。重放本身是一次新调用，会有新的 `call_id`。

## 发布物只含框架

安装包只扫描 `agentboot`。糖尿病和费用审批都放在 `examples/`，给本地运行和测试用，不随框架发布。

## 真实模型按声明做结构化输出

模型实现了 `invoke_structured` 时，结束回答不再靠提示词里的 JSON 约定：

- 没有 Tool，或 `required_tools` 已经成功调用时，这一轮直接按 `SKILL.md` 的 `output` 字段生成 schema。
- 有 Tool 但没有 `required_tools` 时，模型仍可先决定要不要调用 Tool。它不再调用时，下一轮再按同一份 schema 收口。这一轮计入 `max_steps`。
- `LangChainModel` 把这份 schema 交给 `with_structured_output`。
- 返回之后仍用 `output_problems` 检查缺字段和类型。不对就按失败策略处理，`error_kind` 为 `llm`。
- `offline_step` 和没有 `invoke_structured` 的测试模型保持原来的 JSON 文本路径。

## 第二个示例：费用审批

`examples/expense` 用同一套契约跑通非医疗流程。限额在 `check_amount_policy`。主图的兜底字段是 `decision`，不是 `risk_level`。`escalate` 或 `reject` 进入 `expense_escalation`。空计划落到 `policy_reference`。

## 按用途管理模型

模型配置放在 YAML 里，用 `AgentBootApplication(models=路径)` 或环境变量 `AGENTBOOT_MODELS` 加载。密钥不写进文件，配置里用 `api_key_env` 指向环境变量。

内置槽位：

- `route`：主图规划，轻量模型
- `general`：一般文字。Agent 不写 `model` 时用它
- `extract`：从材料里抽字段
- `reason`：强推理
- `vision`：看图片
- `embed`：向量化，给检索 Tool 用
- `rerank`：精排，给检索 Tool 用

每个槽位有一份候选名单，`default` 是默认模型。只有一个模型时可以不写 `default`。默认模型连不上、超时、被限流或返回 5xx 时，按名单里其余模型的书写顺序换下一个。输出缺字段、类型不对、或请求本身不合法，不换模型。

Agent 在 `SKILL.md` 写 `model: reason`。主图没有单独的 `route` 时使用 `general`。声明了槽位但配置里没有，装配时直接报错。实际应答的模型名写在该次模型 span 的 `model_option` 里。

`embed` 用 `catalog.embeddings().embed(texts)`。`rerank` 用 `catalog.reranker().rerank(query, documents)`，返回 `index` 和 `score`。这两类不进入 Agent 的对话循环。

仓库里的示例文件是 `examples/models.yaml`。自建服务与云上模型填法相同，用 `base_url` 指向自己的地址。糖尿病案例的表是 `examples/diabetes/models.yaml`，风险评估 Agent 声明 `model: reason`，指南检索会使用 `embed` 和 `rerank`。费用审批的表是 `examples/expense/models.yaml`，限额判断声明 `model: reason`，制度查询会使用 `rerank`。这两个案例的 `general`、`reason` 和路由都先写了自建地址，云上模型作为备选。
